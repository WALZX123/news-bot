# 新闻简报机器人

从公开 RSS 采集新闻，按关键词、个人兴趣和来源筛选，生成带原文链接的简报并发送到钉钉。CLI 和 Web 使用同一套持久化流水线。新闻入库、分析、发送和成功回执各自记录状态，失败可恢复，送达不明时停止自动重发。

运行环境为 Python 3.13、MySQL 8.0 和 Node.js 24，安装工作台见[项目首页](../README.md)。

## 安装与配置

使用 Python 3.11～3.13 和 MySQL 8.0。Windows 在项目目录执行：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
Copy-Item config.example.yaml config.yaml
```

已有安装沿用自己的 `.venv` 和 `config.yaml`，不要覆盖凭据。`requirements.lock` 固定运行依赖及传递依赖版本；`requirements.txt` 是宽范围兼容声明。更新锁文件后重跑回归。

配置选择顺序：`--config` → `NEWS_BOT_CONFIG` → 项目目录的 `config.yaml`。认证、源管理、编辑和手动任务始终使用同一个绝对路径。支持 `MYSQL_*`、`DINGTALK_WEBHOOK_URL`、`DINGTALK_SECRET`、`AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 环境覆盖。

首次新库初始化：

```powershell
.\.venv\Scripts\python.exe -B main.py --init-db
```

旧版本升级须先停止旧调度器和 Web，再备份数据库及配置，确认旧 MySQL 会话时区。旧库原时区为 UTC+8 时，迁移命令如下。

```powershell
.\.venv\Scripts\python.exe -B main.py --init-db --legacy-timezone=+08:00
.\.venv\Scripts\python.exe -B main.py --check-db
```

若旧库原先使用 UTC，改用 `--legacy-timezone=UTC`；不要照抄其他机器的时区。迁移只转换三个旧表的系统创建/发送时间，原 RSS 发布时间已是 UTC，不再转换。迁移意图和完成版本持久化；中断后重新执行初始化会续做，不会重复减时差。未完成时间迁移时，正常流水线拒绝处理。

初始化账户需要建库/DDL 权限；常规运行账户只需要对应表的 DML、查询及会话锁能力。启动应用不会自动建库或修改表。

## 运行

```powershell
# 只读数据库、迁移和未知送达检查，不采集、不调用模型、不发消息
.\.venv\Scripts\python.exe -B main.py --check-db

# 先采集入库，保留待处理记录；不分析、不推送、不生成报告
.\.venv\Scripts\python.exe -B main.py --fetch-only

# 完整一轮；会调用配置的模型和钉钉，应确认端点、费用和群接收方
.\.venv\Scripts\python.exe -B main.py --once

# 定时运行；每轮重读配置，包含间隔变化
.\.venv\Scripts\python.exe -B main.py
```

Web 也执行同一套筛选、推送窗口和批次流程。时间窗口可跨午夜；时段外新闻保持待处理，不先消耗模型预算。全部兴趣低分时不会强制发送。`max_news_per_run: 0` 表示不另设发送条数上限，但仍受 `max_candidates_per_run`、模型输入、调用和任务时限约束；默认每轮最多评估 100 个候选。

RSS 每源最多十条、最多百个源，有共享总时限、可终止子进程、响应字节上限和逐跳 URL 校验。私网源默认拒绝，确需本地 RSSHub 时用 `allow_private_rss_hosts` 精确指定主机；不要使用宽泛网段白名单。源健康保存在所选配置旁的 `runtime/source-health.sqlite3`。

## Web 管理

取消了默认 `admin` 登录。未设置口令时页面显示配置说明并拒绝登录。可在当前 PowerShell 中设置临时口令后启动：

```powershell
$newsBotPassword = Read-Host '设置后台口令' -AsSecureString
$env:WEB_PASSWORD = [Net.NetworkCredential]::new('', $newsBotPassword).Password
.\.venv\Scripts\python.exe -B web_app.py
```

需要持久口令时，在私密配置的 `web_password` 中保存 Werkzeug 支持的 scrypt/PBKDF2 哈希；不要提交到仓库。`WEB_PASSWORD` 用于当前进程口令覆盖。口令变化会使旧登录失效。正式运行还应配置稳定私密的 `FLASK_SECRET_KEY`，避免多进程或重启导致会话签名不一致。

默认仅 `127.0.0.1:5000`。远程访问使用适合部署环境的 WSGI/HTTPS 和访问控制，并明确 `WEB_TRUSTED_HOSTS`、`WEB_TRUSTED_ORIGINS`，HTTPS 设置 `WEB_COOKIE_SECURE=true`。开发启动器拒绝非回环地址的 debug。页面资源均本地托管，许可证和字节校验清单位于 `web/static/vendor`。

## 数据与恢复规则

- `news_items` 保存原始新闻及处理状态；被筛掉、尚未处理和已发送分别记录。
- `delivery_batches`、`batch_items`、`delivery_attempts` 固定批次 ID、新闻 ID 和发送尝试。只有确认成功的批次更新 `notified` 并产生成功历史。
- 明确失败可重试；分析缓存会复用。超预算的旧批次可缩小，剩余新闻继续 pending；旧非法链接逐条隔离，不阻塞好记录。
- 进程中断或钉钉无法提供可靠回执时记为 `unknown`，等待人工核对。使用 `--check-db` 查看批次 ID，核对平台回执后再人工解除，见[运维说明](OPERATIONS.md)。
- 月、季、年和周报采用北京时间自然周期、结束日不含，按持久周期补跑。原始资料默认保留至少 400 天，待发/未知送达不按普通清理删除。报告显示实际留存范围和样本量，旧版已经删除的历史不会凭空恢复。

输入只有短摘要，模型需把事实与推断分开并引用输入证据；应用只回填输入允许的原文链接。结构校验和来源约束不能替代人的事实核查，尤其数字、背景、因果和争议。
